# DSH 原生界面调整验收（2026-09-21）

## 变更

右侧助手仅嵌入服务器上的 DSH 原生 Web 界面，移除自建聊天框、模式页签、聊天会话存储及 `/api/ai/chat` 接口。服务仅发现和启动 DSH，不提供 Codex 接入。新建会话、输入、发送和模型选择由 DSH 管理。

侧栏首次打开时自动启动原生界面；失败后显示原因并允许手动重试。收起侧栏或切换运行不会重载已有 DSH 会话。不同浏览器操作身份仍使用独立原生进程，不依赖客户端、运行记录或数据库在线。

结果分析中的 DSH 入口准备当前运行和脚本的可复制提示，由使用者粘贴到原生会话发送。保留插件背景说明、脚本版本冲突检查、手工 Python/JSON 编辑以及外部生成报告的轮询显示。服务端包配置模板同步取消 headless 参数；旧配置字段可继续读取，原生启动固定使用 web 模式。

## 验证

- `node --test test/test_result_web.js`：83 项通过，原有部署和配置回归保留；替换已移除的自建聊天测试。
- 相关 Python 测试：123 项通过，1 项旧的可选 headless 命令 smoke 跳过。覆盖原生启动、同源代理、操作身份、已删除聊天路由、结果服务、分析目录、报告与配置管理。
- JavaScript、打包 PowerShell 语法检查及本轮文件 `git diff --check` 通过。
- 独立服务 `http://127.0.0.1:64997` 使用本机已安装的 DSH 命令实际启动；浏览器显示 DeepSeek Harness 原生界面、输入框、会话与模型控件。输入验收草稿后，收起再打开保留草稿；验收后已清除。
- 报告入口生成上下文提示，页面不自动发送消息、不自动改写报告。手工复制回退与报告轮询由自动化回归覆盖。
- 修复手工草稿重新打开后错误沿用服务器新 revision 的问题。两页实际并发编辑验证：旧草稿保存被冲突检查阻止，载入最新版本后原草稿单独保留，可合并再保存；自动化回归同时覆盖读取失败和连续保存。

本轮未发送模型请求，不将界面加载成功表述为模型端点验证。独立预览现已启用本机 DSH；这与此前插件部署改版时故意禁用 DSH 的测试条件不同。原离线交付包尚未重新打包。
