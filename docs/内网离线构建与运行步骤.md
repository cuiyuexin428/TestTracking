# 内网离线构建与运行步骤

适用于：目标机器没有外网，把整个 TestTracking 文件夹拷贝过去后本地编译、运行。

## 一、目标机器前置条件（一次性）

1. Visual Studio 2022，勾选“使用 C++ 的桌面开发”工作负载（MSVC v143 x64 工具集）。
2. CMake >= 3.16，安装时勾选 “Add CMake to the system PATH”。
3. 不需要网络，不需要 Git、vcpkg 或其他包管理工具。

检查是否就绪：

```powershell
cmake --version
```

## 二、拷贝项目

把整个 TestTracking 文件夹拷贝到目标机，例如 `D:\WorkSpace\TestTracking`。

必须完整包含：

- `third_party`：已编译安装的第三方库（libzmq、abseil、protobuf、nlohmann json、tinyxml2、concurrentqueue、pgsql）
- `third_party_src`：第三方库源码包，缺库时用于离线重建

注意：不要只拷 git 仓库内容而漏掉上面两个目录；建议路径不含中文和空格。

## 三、一键自检 + 编译

打开 PowerShell，进入项目根目录：

```powershell
cd D:\WorkSpace\TestTracking
powershell -ExecutionPolicy Bypass -File tools\verify_offline_build.ps1
```

脚本依次执行：

1. 检查 cmake 和 MSVC C++ 工具链
2. 检查第三方库安装标志，缺失时自动从 `third_party_src` 离线编译安装
3. 检查 PostgreSQL 客户端 libpq（优先项目内 `third_party\pgsql`）
4. cmake configure（x64）+ Debug 并行编译

看到 `RESULT: ALL PASS` 即编译成功。

## 四、编译产物位置

- 目录：`build\offline_verify\bin\Debug`
- 主要程序：`scheduler.exe`（调度程序）、`client.exe`（客户端）
- 插件：`coverage.dll`、`demo.dll`
- 依赖：`common.dll`、protobuf/abseil/libpq 等 DLL
- 配置：`config\scheduler.json`、`config\client.json` 已拷贝到 exe 同目录

## 五、日常构建（第二次以后）

```powershell
cmake -S . -B build -A x64
cmake --build build --config Debug
```

产物在 `build\bin\Debug`；也可以继续使用 verify 脚本（产物在 `build\offline_verify`）。

## 六、要运行还需要

编译本身不依赖数据库，但运行调度/客户端需要：

- PostgreSQL 数据库服务器（内网安装一个，按配置建库/账号）
- 测试数据集（stp 文件）、StepTest.exe 及其运行依赖、OpenCppCoverage 命令，按部署规范放到客户端程序目录
- 防火墙放行调度端口（默认 5555）

## 常见问题

| 现象 | 处理 |
| --- | --- |
| cmake not found | 安装 CMake 并加入 PATH |
| MSVC C++ tools installed FAIL | VS2022 未安装 C++ 桌面开发工作负载 |
| libpq not found | 确认 `third_party\pgsql\include\libpq-fe.h` 存在，或设置 `PG_ROOT` 环境变量 |
| 第三方库缺失 | 确认 `third_party_src\downloads` 完整，脚本会自动离线重建；PostgreSQL 的 zip 只在文件夹里、不入 git |
