# 内网离线部署操作步骤（全自动）

目标：把 TestTracking 拷贝到无网络的服务器后，只运行一个脚本，完成：

- 项目编译
- PostgreSQL 安装、初始化、启动（使用随包携带的 PostgreSQL 17 二进制）
- 数据库 testtracking 自动创建
- stp 数据集部署 + manifest 重新生成
- 调度程序配置生成
- 客户端全量包打包（client.exe + 插件 + StepTest + stp 数据集 + OpenCppCoverage）

之后只需要把客户端全量包拷贝到客户机，运行 start_client.bat 即可。

## 一、服务器一次性准备

1. 安装 Visual Studio 2022，勾选“使用 C++ 的桌面开发”（MSVC v143 x64）。
2. 安装 CMake >= 3.16，勾选加入 PATH。
3. 以管理员身份操作（为了注册 PostgreSQL 服务、开放防火墙；不以管理员运行也能用 pg_ctl 启动，但不会注册服务/开防火墙）。

## 二、拷贝项目

把整个 TestTracking 文件夹拷贝到服务器，例如 `D:\WorkSpace\TestTracking`。

必须完整包含：

- `third_party`：第三方库安装产物（含 PostgreSQL 服务端二进制）
- `third_party_src\downloads`：第三方源码包（离线重建用）
- `tools`：全部脚本

只拷贝 git 仓库内容是不够的，postgresql-*.zip 和 third_party 都不在 git 仓库里。

## 三、修改部署配置（关键）

编辑 `tools\offline_deploy.json`，这是唯一需要手动维护的配置：

| 字段 | 含义 |
| --- | --- |
| `dataset_dir` | stp 数据集源目录（可带任意层级子目录） |
| `dataset_version` | 数据集版本号，与调度/客户端约定一致 |
| `step_test_exe` | 测试程序 exe 当前路径（例如 StepTest.exe） |
| `engine_src_dir` | 引擎源码目录（可选；留空则客户端包不携带源码） |
| `program_version` | 测试程序版本号 |
| `opencppcoverage_dir` | OpenCppCoverage 安装目录 |
| `engine_dlls` | 需要统计覆盖率的引擎 DLL 列表（OpenCppCoverage --modules） |
| `server_ip` | 留空则自动探测本机 IPv4 |
| `server_port` / `db_port` / `db_name` / `db_user` / `db_password` | 调度端口和数据库连接 |
| `package_out_dir` | 客户端全量包输出目录（相对项目根） |
| `worker_id` / `task_threads` | 客户端默认工作名和任务线程数 |
| `task_size` / `store_cov` | 覆盖率插件任务划分参数；`store_cov` 控制客户端是否保留原始 cov 行供后处理合并 |

**stp 初始数据变化时**：更新 `dataset_dir`（或更新源目录内容）和 `dataset_version`，脚本会自动重新部署数据集并重新生成 `manifest.txt`（子目录递归，manifest 记录相对路径和文件大小）。

**测试程序变化时**：更新 `step_test_exe`、`engine_src_dir`（如需携带源码）和 `program_version`；换引擎时同步更新 `engine_dlls`，脚本会自动重新打包 testenv\program。

版本号必须与服务端 `expected_program_version` / `expected_dataset_version` 一致，脚本会同时写入调度配置和客户端包，保持一致。

## 四、一条命令完成全部

```powershell
cd D:\WorkSpace\TestTracking
powershell -ExecutionPolicy Bypass -File tools\setup_offline_server.ps1
```

脚本依次执行：

1. 工具链检查 + Debug 编译（产物在 `build\offline_verify\bin\Debug`）
2. PostgreSQL 安装/初始化/启动（数据目录 `runtime\pgdata`，端口默认 5432），创建数据库 `testtracking`
3. 数据集部署到 `runtime\dataset`，重新生成 `manifest.txt`
4. 生成调度配置 `build\offline_verify\bin\Debug\config\scheduler.json`
5. 打包客户端全量包到 `dist\client_package`
6. 开放防火墙端口 5555 / 5432

看到 `=== Setup complete ===` 即全部完成。

常用开关：

```powershell
# 跳过某一步（例如只更新程序/数据集后重打包）
-File tools\setup_offline_server.ps1 -SkipBuild -SkipDatabase -SkipFirewall

# 用 Release 编译
-File tools\setup_offline_server.ps1 -Config Release
```

## 五、启动调度程序

运行脚本自动生成的 `runtime\start_scheduler.bat`，或手动：

```powershell
cd D:\WorkSpace\TestTracking\build\offline_verify\bin\Debug
.\scheduler.exe config\scheduler.json
```

## 六、客户端部署

把 `dist\client_package` 整个目录拷贝到客户机（例如 `D:\Client\client_package`），运行：

```
start_client.bat
```

客户端配置（endpoint、数据库连接、worker_id、任务线程数、程序/数据集版本）已经由脚本生成好，不需要手工修改。

## 七、只重新编译/自检

```powershell
powershell -ExecutionPolicy Bypass -File tools\verify_offline_build.ps1
```

结果 `RESULT: ALL PASS` 表示离线编译环境正常。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 数据库服务没有启动 | 管理员运行脚本；或单独运行 `tools\init_postgres_offline.ps1` |
| 防火墙规则失败 | 以管理员运行，或手动开放 5555/5432 |
| manifest 没有更新 | 检查 `dataset_dir` 是否正确，脚本每次都会重新生成 |
| 客户端注册被拒绝 | 检查客户端 `version.txt` 与服务端 `expected_*_version` 是否一致 |
| 目标机无网络 | 整个文件夹拷贝（含 third_party 与 downloads），无需联网 |
