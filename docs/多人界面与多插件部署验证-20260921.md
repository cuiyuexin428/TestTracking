# 多人界面与多插件部署验证

本记录针对本轮结果服务和浏览器界面的修改。真实服务包、客户端进程及调度恢复的整体验收见[完整包验收记录](多插件多用户多任务完整包验收-20260921.md)。

## 实现

- 客户端部署配置允许同时启用多个插件。向导将“启用哪些插件”与“正在编辑哪个插件”分开，coverage、stpcompare 的 DLL、业务程序、数据、执行模式独立保存；共用客户端执行/更新时间窗。两插件选择不同数据制品时自动分配独立槽位。
- 客户端页使用服务端 `physical_client_id` 聚合插件 Worker，分别展示状态、资源、当前任务。部署目标使用物理客户端基础身份；任务目标仍按当前插件的独立 Worker 选择，不会因另一插件忙而禁用本插件。
- `client.task_threads` 明确为每插件并发数，界面与现行文档已同步。
- DSH 原生界面原来只有独立进程，实际持久会话和工作区仍共用 DSH_HOME。本轮将 session logs、workspace storage、attachments 通过 DSH 原生配置覆盖到每 operator 的独立目录；保留安装环境的模型配置、凭据和 skills。
- 同一浏览器配置文件的多个页面共用其 operator；不同使用者使用独立浏览器配置文件。项目文件和数据库仍共享，不引入登录或权限隔离。

## 验证

- `node --test test/test_result_web.js`：最终 86 项通过，包含多插件草稿切换、程序模式保留、不同数据集槽位、物理机器分组与部署目标，以及自定义插件和未编辑字段共享制品槽位的保留。
- `runtime/python/python.exe` 运行 `test_dsh_proxy.py`、`test_management.py`、`test_deployments.py`、`test_reports.py`、`test_program_bindings.py`、`test_result_service.py`、`test_management_http.py`、`test_plugin_views.py`、`test_server_plugins.py`：167 项测试，常规执行 166 项通过、1 项需要本机 DSH 的测试跳过。
- 单独设置 `TESTTRACKING_DSH_WEB_COMMAND` 指向本机可用 `dsh.cmd`，运行原生双用户测试通过。实际启动两个 DSH Web 进程；A 新建工作区、会话并重命名，B 的工作区和会话列表保持为空；等待 DSH 原生异步落盘后停止并重启 A，仍能读取 A 的工作区与会话。此项通过原生 RPC 验证，没有调用模型服务。
- 报告脚本并发保存：两个编辑者携带同一 revision 同时提交，仅一个成功，另一个 HTTP 409 语义冲突，最终文件和审计对应成功者。部署状态原有并发 CAS、配置冲突保留草稿、共享报告编辑冲突回归继续通过。

DSH 历史保存在配置工作目录的 `runtime/result_service/dsh_web/<operator_id>/`。此目录属于运行数据，不作为客户端插件或业务数据制品分发。
