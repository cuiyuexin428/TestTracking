# 基础客户端批量部署验收

本轮将部署入口改为物理机器：新机器先启动基础 Agent，再由服务端页面批量选择空闲客户端，下发插件、程序、数据和运行安排。平台为 Windows x64。

## 实现范围

- Bootstrap 包没有业务插件、程序、数据或插件数据库连接；首次启动生成独立身份，重启后沿用。没有插件时仍独立发送心跳。
- 客户端列表展示物理机器及各插件 Worker。任意插件有在途任务、执行任务或未确认结果，整台机器不可配置。因程序版本不匹配而处于启动中的空闲机器仍能接收修复配置。
- 批量配置从空增量开始，每台独立合并，不复制第一台完整配置。保留不同机器的未编辑字段和共享制品引用；预览中的密码掩码不回传覆盖实际连接。
- 发布在调度器派单队列中原子预占所有目标机器，再一次性保存全部部署期望；旧 revision 或任意忙碌机器导致整批拒绝。等待更新期间阻断所有插件派单，更新时间窗关闭时保留预占等待。
- 下载完整制品并校验内容，自动停止旧 Worker、切换配置、启动新 Worker；不需要 DLL 热加载或手动重启整台客户端。
- 下载失败不自动重试同一部署。激活失败先停止全部新 Worker、恢复旧配置，再报告失败；旧程序无法通过新版服务端注册时也能重新发布修复。成功部署仍要求所有新 Worker 注册就绪。
- 前端保留增量草稿、单台历史回退、目标切换与多人冲突处理，部署区域移至客户端页面。DSH 保持原生界面。

## 本轮发现并修复的问题

1. 普通下载失败释放预占后可能自行重试同一版本，已增加持久失败记录和服务端失败状态拦截。
2. OpenCppCoverage 的较深目录在带 GUID 的临时解压目录下超过 Windows 路径限制，已把暂存目录移到 objects 下，保持最终完整 SHA 缓存和校验。
3. 服务端绑定新程序版本后旧 Worker 无法注册，原“启动中不可配”限制阻断升级，已按整机任务状态允许空闲机器修复。
4. 更新失败后等待旧 Worker 注册才报告终态可能长期锁住客户端，已分离“配置恢复完成”和“旧插件就绪”。
5. 协议测试的假调度器在等待 Agent 退出期间停止处理消息，引入旧注册请求干扰重启测试；已保持测试调度器持续响应并与生产 ROUTER 的接管设置一致。
6. 部署详情弹层仍位于隐藏的插件页内，从客户端页打开后导致弹层不可见、页面被锁住。已将共享弹层移至页面之外，并增加 HTML 结构及打开/关闭交互回归。
7. 客户端已回报就绪但没有附带说明时，详情误显示“尚未收到客户端回报”。已按实际回报状态展示摘要，已生效部署不再显示等待应用的提示。

首次完整包验收还发现测试 ZIP 构造器遗漏 OpenCppCoverage 依赖的空目录，已保留全部目录后重新上传、执行，没有裁减工具内容。失败证据与后续成功证据均保存在 `real-test/bootstrap-round/evidence`，历史数据库结果未删除或回写。

## 启动和停止此验收环境

环境已在运行时直接访问上述网址，不要重复启动。停止时在 PowerShell 创建该环境根目录下的停止请求文件：

```powershell
New-Item -ItemType File -Force -Path 'C:\WorkSpace\TestTracking-02\real-test\bootstrap-final\stop.request'
```

验收守护进程检测到文件后，会停止本轮管理的两个客户端、结果服务、调度器及独立 PostgreSQL，保留包、数据库和证据。等待该守护进程退出后，使用以下命令重新启动已有环境：

```powershell
& 'C:\WorkSpace\TestTracking-02\runtime\python\python.exe' -B `
  'C:\WorkSpace\TestTracking-02\test\run_bootstrap_acceptance.py' `
  --out 'C:\WorkSpace\TestTracking-02\real-test\bootstrap-final' `
  --serve-existing
```

`--serve-existing` 自动保持服务运行，只启动已有包和原数据库，不重新构建、不重跑验收、不清空结果；旧的 `stop.request` 会在启动已有环境时移除。命令持续运行，显示 `READY http://127.0.0.1:63696` 后可访问。再次停止仍创建同一路径的 `stop.request`。如果上次守护进程或数据库尚未退出，启动检查会拒绝复用，需先完成正常停止。

## 验证边界

业务可执行程序使用本仓库编译的 native acceptance fixture，真实调用 OpenCppCoverage、生成新老程序各两份 info、写入 PostgreSQL，但不实现正式 STEP 几何转换。正式业务程序、全量 STP 数据以及跨机器防火墙和数据库连通性仍需在内网验证。

本节的包验收运行在同一台 Windows x64 机器上，以两个独立客户端进程实例覆盖多客户端与多插件流程；多人修改冲突通过独立操作请求验证。浏览器实际操作范围见上一节；跨机器并发及内网 DSH 模型端点仍需在目标环境验证。

批量部署期望一次性保存，各机器独立激活或回退，不保证同时切换。服务端插件及程序匹配配置的重启仍由维护者执行；客户端框架 EXE 自更新、大包断点续传不在本轮范围。使用说明见 [基础客户端与批量部署](基础客户端与批量部署.md)。
