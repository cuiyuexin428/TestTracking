# 管理功能补齐与发布验收（2026-09-16）

本轮承接 `整体审查-20260916.md` 的已确认问题及管理页面缺口。目标环境为 Windows x64 可信局域网；任务执行与数据库结果分析独立，客户端暂时携带全量数据。

## 已实现的页面行为

| 页面 | 实际能力 |
| --- | --- |
| 运行总览 | 从数据库展示任务进度；连接本机调度接口启动/停止运行、唤醒客户端，明确区分进程在线和持久化状态 |
| 客户端 | 显示实际注册的 worker、插件、心跳、资源、任务及 attempt，自动刷新；调度离线有明确提示 |
| 历史运行 | 搜索和分页；可按运行 ID 打开早期结果 |
| 结果分析 | 仅依赖已入库数据；按插件编辑/保存/替换 Python 脚本并生成交互 HTML，保留上次成功报告 |
| 插件与配置 | 分开展示执行插件与分析适配器；编辑调度、结果服务/AI、客户端模板，校验、备份、冲突检测及重启提示 |
| 运行日志 | 读取实际日志，按文件、级别、文字过滤，控制返回行数并自动刷新 |
| AI 助手 | 使用服务器账户的 Codex/DSH；DSH 原生网页通过主界面代理，任务服务离线仍可聊天及分析 |

配置编辑写入明确配置文件；不向其他机器推送客户端配置。修改后按提示重启对应进程。业务程序、数据路径和 worker_id 应在部署到各客户端时设置。

## 本轮复审发现及修复

1. 空数据库同时启动调度器和多个客户端会竞争创建 PostgreSQL 表。统一短事务内的 schema 初始化锁，覆盖框架和两个内置插件。
2. 结果分析若在长事务内持有建表锁，会阻塞客户端初始化。将 coverage 后处理初始化移到长事务前；已有列不再重复申请 ALTER TABLE 独占锁。
3. 配置文件是否需要重启不能只比较结果服务启动时的文件摘要。调度配置改为核对实际加载配置、配置路径和进程实例。
4. 无效管理命令的类型错误需返回 HTTP 400；保存配置的校验应与现有合法配置保持一致。
5. 状态快照更新延迟时应说明数据时效；中等分辨率下 AI 侧栏应为主区保留操作空间。
6. 源码一键离线部署也需生成管理地址、结果服务配置及启动入口，不能只更新发布包路径。
7. 源码交付排除本机旧启动脚本、临时数据库、日志、会话、PID 和构建缓存，保留源码及离线依赖。
8. 定制调度配置移到 `runtime/scheduler.json`，防止内网修改代码并重新编译时被构建模板覆盖。无 Windows 服务模式下，启动脚本只启动本部署明确记录的 PostgreSQL 数据目录。
9. 数据源与将被替换的目标目录相同时，在删除前拒绝操作并保留原文件，覆盖源码部署与客户端数据更新。
10. 删除旧的“按 OpenCppCoverage 输入目录名清理目标目录”分支，避免误删业务程序；独立复核及回归通过。
11. 源码交付排除不参与运行和编译的 pgAdmin 展开目录，避免 Windows 解压长路径；服务端 ZIP 保留发布清单的完整文件集。

## 部署验收边界

- 正式业务 EXE/DLL、OpenCppCoverage、完整 STP 数据和内网模型端点由内网提供；本机 dry-run 不等同于真实业务程序验收。
- 编译机需具备 VS2022 C++ 工具链、Windows SDK、CMake。此交付保留 C++ 第三方库及源码缓存、Python 运行时和分析 wheelhouse；不包含 VS 离线安装源。
- 最终内网双机验收仍需执行真实任务、结果报告、DSH 对话及服务端/客户端分别异常退出后的恢复。
- 本轮结论限定为已覆盖场景没有未解决的阻塞缺陷；长期边界见 `已知限制.md`。
