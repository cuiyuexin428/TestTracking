# 服务端插件包格式与安装

服务端插件包把调度器插件 DLL、结果查询适配器、结果区初始展示、AI 背景说明和可选任务清单一起安装。客户端插件、业务程序和 STP 数据仍通过客户端部署制品分发；这个包不会更新客户端，也不会替换框架 EXE。

包格式为 ZIP，根目录必须有 `server_plugin.json`。上传时使用 `kind=plugin`、`name=<plugin>-server`，版本与清单一致。例如客户端插件可叫 `coverage`，服务端包叫 `coverage-server`，避免同一制品名称和版本指向不同内容。

## 生成包

在源码根目录使用项目自带 Python，无需访问互联网：

```powershell
.\runtime\python\python.exe .\tools\build_plugin_bundle.py `
  --plugin-dir .\plugins\coverage `
  --dll .\build\rt\bin\Release\coverage.dll `
  --version 1.1.0 `
  --output .\dist\coverage-server-1.1.0.zip
```

`--dll` 请使用实际 Release 输出路径。插件 DLL 必须与部署中的框架来自兼容的同一构建；包校验不加载 DLL，因此不承诺能够检查 C++ ABI 兼容性。

可选参数：

- `--plugin`：插件 ID，默认使用 `--plugin-dir` 的目录名。
- `--defaults`：新插件默认调度配置的 JSON 文件，不含 `dll`、`enabled`、`stp_manifest`。
- `--manifest`：新插件的任务数据清单，只包含清单，不包含客户端 STP 数据。
- `--dependency`：插件额外的本地运行文件，复制到包内 `bin`，可重复指定。框架自身 DLL 仍应使用框架匹配的版本。

工具只读取和校验 Python 源码，不执行适配器或分析脚本；验证成功后才替换输出 ZIP。同样的文件与配置会生成相同 ZIP 内容。

## 清单

```json
{
  "schema_version": 1,
  "package_type": "testtracking-server-plugin",
  "plugin": "coverage",
  "version": "1.1.0",
  "scheduler": {
    "dll": "bin/coverage.dll",
    "defaults": {
      "task_size": 25,
      "store_type": "postgres"
    }
  },
  "resources": {
    "view": "result_view.json",
    "adapter": "result_adapter.py",
    "ai_context": "AI_CONTEXT.md",
    "report_template": "result_report.py",
    "manifest": "dataset/manifest.txt"
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `scheduler.dll` | 必需，包内调度插件 DLL 的相对路径。 |
| `scheduler.defaults` | 可选，只用于首次安装；升级保留现有业务设置。新插件固定为 `enabled=false`。 |
| `resources.view` | 必需，符合现有结果展示 schema 的 JSON，`plugin` 必须与本包一致。可仅提供空 widgets，供后续 AI 分析脚本使用。 |
| `resources.ai_context` | 必需，非空 UTF-8 Markdown，最多 64 KiB，说明插件功能、持久化数据及字段语义。 |
| `resources.adapter` | 可选，UTF-8 Python 文件，定义 `create_result_adapter(options)`。安装只做语法检查，结果服务重启后才加载。 |
| `resources.report_template` | 可选，UTF-8 Python 初始分析模板；不覆盖使用者已经保存的分析脚本。 |
| `resources.manifest` | 可选，首次安装且没有 `stp_manifest` 时写入配置；升级保留已有清单路径。 |

适配器和模板为独立 Python 文件，可以使用已安装的公共依赖。本格式不自动安装 pip 包或适配器的额外 Python 模块。覆盖率提供最小 STP 集合分析模板；其他插件的具体分析脚本可在内网编写。

包内路径使用 `/`，禁止绝对路径、`..`、Windows 特殊文件名、大小写冲突、链接和加密条目。最多 4096 个条目，单文件最多 512 MiB，解压总大小最多 1 GiB。制品的 SHA-256 和大小在安装前再次核对。插件包属于管理员提供的可信程序代码，不应将格式校验理解为代码沙箱。

## 接口流程

先通过已有制品上传接口上传 ZIP：

```text
POST /api/artifacts/upload?kind=plugin&name=coverage-server&version=1.1.0&filename=coverage-server-1.1.0.zip
Content-Type: application/octet-stream
```

响应中的 `artifact_id` 用于只读预览：

```text
POST /api/server-plugins/preview
Content-Type: application/json

{"artifact_id":"上传返回的标识"}
```

预览返回插件、版本、文件清单、安装或升级动作、资源角色、当前配置版本、重启提示。预览不创建目录、不加载 DLL、不导入 Python 代码，也不更改服务状态。真正安装时会重新检查任务状态。

把预览返回的两个配置版本原样带入安装请求：

```text
POST /api/server-plugins/install
Content-Type: application/json

{
  "artifact_id": "上传返回的标识",
  "scheduler_revision": "预览返回的 scheduler_revision",
  "result_service_revision": "预览返回的 result_service_revision",
  "operator_id": "当前界面使用者标识"
}
```

配置已被其他操作修改时返回 409，需要重新预览。目标插件有未完成运行时不能切换；任务状态或持久化状态读取失败时也不能继续。该限制保护恢复使用的原 DLL、清单与业务配置。安装前以及文件准备结束后都会复核任务状态，网页任务创建与安装使用同一管理锁。

## 生效与回退

安装在制品仓库的 `server-plugins/installations/<installation_id>` 创建独立目录，并为所有现有插件生成一份完整的结果资源快照。调度 DLL、AI 上下文、适配器和展示文件不会原地覆盖；升级缺省的可选适配器或模板会从新的资源快照中移除，但旧部署文件仍保留。使用者的 `analysis_scripts_dir` 和已生成报告不变。

两份配置使用版本校验并在同一管理锁下写入；如果中途发生写入错误，恢复原配置及调度器待重启标记。安装目录内保留 `scheduler.before.json`、`result_service.before.json` 和安装记录。事务日志 `server-plugins/pending-install.json` 用于进程异常退出后恢复部分写入；如果已经全部提交，只清理日志。如果配置在异常后又被外部修改，则停止自动恢复并提示核对，避免覆盖人工修改。

安装响应包含 `restart_required: ["scheduler", "result_service"]`。安装不会自动重启进程；需要按现有启动方式重启这两个服务。安装后的配置在重启前不能用于从页面创建新任务；新插件需补齐本地数据库、程序版本等业务设置并启用，再安排对应客户端执行。

调度资源路径优先相对 `workspace` 保存，结果资源路径相对结果服务配置所在目录保存，保持现有从源码根目录或服务端包根目录启动的约定。未配置 `workspace` 或资源与目标目录跨 Windows 盘符时使用绝对路径，搬移后需要调整。

需要人工回退时，先确认目标插件没有未完成运行，停止调度器和结果服务，再核对备份后恢复这两份配置并重启；不要删除旧安装目录或单独覆盖正在使用的 DLL。回退不是数据库 schema 降级工具，涉及插件数据格式变化时由该插件提供兼容处理。
