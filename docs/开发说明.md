# 开发说明

面向项目维护者与插件开发者。前提：**Windows x64**；本文命令以 PowerShell 为主。

- 构建产物只在本机使用；交付给运维的路径见 [部署与运行](部署与运行.md)。
- 相关文档：[设计说明](设计说明.md)（模块与状态机）、[已知限制](已知限制.md)（验证边界）。

## 1. 工具链前置

| 组件 | 要求 | 说明 |
| --- | --- | --- |
| Visual Studio 2022 | C++ 桌面工作负载（v143） | `CMakeLists.txt` 要求 C++17；MSVC 下追加 `/utf-8` |
| CMake | ≥ 3.16 | `cmake_minimum_required(VERSION 3.16)` |
| PostgreSQL | 提供 `include/libpq-fe.h` 与 `lib/libpq.lib` | 由 `cmake/find_package.cmake` 定位 |
| Python 3 | 仅测试与结果服务需要 | CTest 会优先使用 `runtime/python/python.exe`（随包便携运行时） |

`PG_ROOT` 的定位顺序（`cmake/find_package.cmake`）：`-DPG_ROOT=<root>` → 环境变量 `PG_ROOT` → 依次探测 `C:/Program Files/PostgreSQL/*`、`C:/pgsql`、`<项目>/third_party/pgsql`、`C:/WorkSpace/ThirdParty/pgsql`。都找不到时 CMake 直接报错。

## 2. 第三方依赖

第三方库**不参与项目编译**，以安装产物形式随目录迁移（`tools/README.md`）：

```powershell
# 首次或在无网络的新机器上重建（下载包已在 third_party_src\downloads）
powershell -ExecutionPolicy Bypass -File .\tools\build_third_party.ps1

# 强制重建；镜像加速 GitHub 下载
powershell -ExecutionPolicy Bypass -File .\tools\build_third_party.ps1 -Force
powershell -ExecutionPolicy Bypass -File .\tools\build_third_party.ps1 -Mirror https://ghproxy.net/
```

包含：libzmq 4.3.5（静态）、abseil-cpp 20230802.3、protobuf 25.3、moodycamel、nlohmann/json 3.11.3、tinyxml2。产物布局为 `third_party/`（安装）与 `third_party_src/`（源码与构建目录）。

## 3. 构建

```powershell
cmake -S . -B build/rt
cmake --build build/rt --config Debug --parallel 8
```

说明：

- 所有 exe 与 DLL 输出到同一目录 `build/rt/bin/<Config>`，`common.dll` 与每个 exe 同目录，运行时无需设置 `PATH`（`CMAKE_RUNTIME_OUTPUT_DIRECTORY`）。
- `deploy_third_party` 与 `deploy_libpq` 两个 ALL 目标负责把 protobuf / abseil / libpq 及其依赖拷到该目录；每个可执行目标都依赖它们（`attach_runtime_dependencies`）。
- 若构建目录与其他工具默认值不一致，打包时必须显式传 `-BinDir`；`tools/build_package.ps1` 与 `tools/build_server_package.ps1` 默认读取 `build\offline_verify\bin\Release`（`tools/README.md`）。
- Release/Debug 均可构建（第三方静态库两种配置都有产物）；但**部署包只接受 Release**：`build_package.ps1` 对非 Release 配置直接抛错，理由是 Debug 运行库不可再分发。

## 4. 测试

### 4.1 全部测试（CTest）

```powershell
ctest --test-dir build/rt -C Debug --output-on-failure
```

- 原生用例：`test_common`、`test_zmq`、`test_config`、`test_messages`、`test_stpcompare_restore`、`test_coverage_client`、`test_client_runtime`、`test_client_protocol`、`test_scheduler_protocol`、`test_plugin_runtime`。
- 结果服务与部署链的 Python 用例由 `test/CMakeLists.txt` 注册（`test_result_service`、`test_management*`、`test_deployments*`、`test_deployment_profiles*`、`test_deployment_rollouts`、`test_artifacts`、`test_reports`、`test_dsh_proxy` 等）；Windows 上另有 `test_client_bootstrap`、`test_client_update`、`test_package_portability`、`test_client_deployment_integration`。
- 前端用例在找到 Node.js 时注册：`test_result_web`、`test_deployment_profiles_web`。
- 需要真实 PostgreSQL 的集成用例只在 Windows + 找到 Python + `PG_BIN_DIR/initdb.exe` 时才注册，并各自创建私有实例：`test_schema_startup`、`test_management_integration`、`test_coverage_settle`、`test_runtime_integration`、`test_deployment_rollout_integration`、`test_tools_integration`、`test_plugin_runtime_db`。

### 4.2 单独运行 Python 用例

```powershell
cd test
python -m unittest discover -s . -p "test_deployment_rollouts.py" -t .
```

用例自行把项目根加入 `sys.path`（例如 `test/test_deployment_rollouts.py` 头部），因此从 `test/` 目录运行最省事。

## 5. 插件接口

框架只负责路由、账本、租约与恢复；业务全部在插件里。两端以同一个 `plugin_type` 绑定。

### 5.1 服务端插件（`common/inc/common/TaskPlugin.h`）

```cpp
class TaskPlugin {
  virtual std::string pluginType() const = 0;
  virtual bool init(const std::string& config) = 0;
  virtual bool validateClient(const ClientInfo&, const std::string& client_message,
                              ValidationResult& result) = 0;
  virtual bool validateRunParameters(const std::string&, std::string&) const { return true; }
  virtual bool plan(const RunRequest&, const std::vector<ClientInfo>& clients) = 0;
  virtual bool requestTask(const ClientInfo&, const std::string& request_payload, Task& task) = 0;
  virtual bool processResult(const TaskResult& result) = 0;
  virtual bool runFinished() = 0;
  virtual void cancel() = 0;
  virtual void requeue(const std::vector<std::string>& task_ids) = 0;
  virtual bool saveCheckpoint(const std::string& run_id) = 0;
  virtual bool restore(const std::string& run_id) = 0;
};
```

关键约定（来自头文件注释与框架实现）：

- `plan()` 必须在返回 `true` 之前**把任务清单持久化**；框架只管理待派发/已提交账本。
- 所有运行时回调都在调度器 worker 线程上串行执行，包括 STOP、checkpoint 与 cancel；`processResult()` 必须幂等，返回 `false` 表示框架保持该次尝试在途。
- 持久进度暂时不可读或与部署不兼容时抛 `common::RecoveryBlocked`：框架会保留恢复索引，修复存储/配置后允许重试，而不是把 run 判为丢失。
- `validateRunParameters()` 是相对较新的接口，**升级时需要同时重建调度器与全部插件 DLL**（`result_service/README.md` 的升级说明）。

DLL 导出：

```cpp
extern "C" __declspec(dllexport) common::TaskPlugin* CreatePlugin();
extern "C" __declspec(dllexport) void DestroyPlugin(common::TaskPlugin*);
```

### 5.2 客户端插件（`common/inc/common/WorkerPlugin.h`）

```cpp
class WorkerPlugin {
  virtual std::string pluginType() const = 0;
  virtual bool init(const std::string& config) = 0;
  virtual bool collectRegistrationInfo(std::string* payload) = 0;
  virtual RegisterOutcome handleValidationReply(const std::string& reply_payload) = 0;
  virtual bool execute(const Task& task, TaskResult& result) = 0;
  virtual bool execute(const Task& task, TaskResult& result,
                       const CancellationToken& cancellation);   // 默认转发到上面
  virtual std::string heartbeatInfo() const;                     // 可选，仅展示
};
```

- `execute()` 最多按 `client.task_threads` 并发；默认实现直接转发，**要支持取消就必须重写带 `CancellationToken` 的重载**，并在等待与发布文件结果之前检查取消状态。
- `RegisterOutcome` 只有三种：`kReady`（校验通过进入 READY）、`kRetry`（已处理回复，重新发起注册）、`kFailed`（无法满足，放弃）。

DLL 导出：

```cpp
extern "C" __declspec(dllexport) common::WorkerPlugin* CreateClientPlugin();
extern "C" __declspec(dllexport) void DestroyClientPlugin(common::WorkerPlugin*);
```

### 5.3 新增插件的落地步骤

1. 在 `plugins/<name>/` 建 `CMakeLists.txt`，产出 `scheduler` 与 `client` 两个目标所需的 DLL；参考 `plugins/coverage/CMakeLists.txt`。
2. 服务端：实现 `TaskPlugin`，在 `scheduler.json` 的 `plugins.<name>` 里配置 `dll`、`enabled` 与业务键。
3. 客户端：实现 `WorkerPlugin`，在 `client.json` 的 `plugins.<name>` 里配置 `dll`、`enabled`、`dry_run` 与业务键。
4. 结果侧：可选 `result_view.json`（声明式视图）；需要从数据库计算分析对象时增加 `result_adapter.py`，导出 `create_result_adapter(options)`，返回带布尔 `configured` 与 `summary(connection, run_id)` 的对象。
5. 需要专用后处理时增加独立工具（参考 `plugins/coverage/src/settle_coverage.cpp` + `tools/settle_coverage.ps1`）。
6. 在 `test/CMakeLists.txt` 注册用例。

## 6. 本地调试

### 6.1 用 demo 插件跑通协议

`demo` 是最小的端到端样本，两端都已实现，默认关闭。

```powershell
# 1) 开启 demo 并关闭其它插件（两个配置文件都要改）
#    scheduler/scheduler.json -> plugins.demo.enabled = true
#    client/client.json       -> plugins.demo.enabled = true, plugins.coverage.enabled = false

# 2) 启动调度器（第一个参数是配置文件路径，默认 config/scheduler.json）
.\build\rt\bin\Debug\scheduler.exe .\scheduler\scheduler.json

# 3) 另开一个终端启动客户端（第一个参数是配置文件路径，默认 config/client.json）
.\build\rt\bin\Debug\client.exe .\client\client.json

# 4) 提交/停止 run：直接在调度器终端输入（stdin 命令）
#    run demo d1
#    stop demo
```

- 调度器 stdin 支持 `run <plugin_type> <dataset_version> [params]` 与 `stop <plugin_type>`（`scheduler/src/main.cpp`）。
- 客户端配置中的 `plugins.demo.task_sleep_ms` 控制模拟耗时。
- 正式提交与停止请走结果服务网页或管理接口，那里会带上 run ID。

### 6.2 只调客户端协议

`client.exe --worker-plugin <name> --config <path>` 直接以 Worker 身份运行；Agent 自动启动时还会附加 `--qualify-worker-id`、`--stop-event`、`--drain-event`、`--ready-event`（`client/src/ProcessAgent.cpp`），手工调试一般不需要这些事件参数。

### 6.3 只调结果服务

```powershell
cd result_service
python .\launcher.py --config .\config.example.json
```

- 配置可用环境变量覆盖：`RESULT_SERVICE_HOST`、`RESULT_SERVICE_PORT`、`RESULT_SERVICE_DB`、`RESULT_SERVICE_WORKSPACE`、`RESULT_SERVICE_PLUGIN_VIEWS`、`RESULT_SERVICE_PLUGIN_ADAPTERS`、`RESULT_SERVICE_PLUGIN_AI_CONTEXTS`（`result_service/app/config.py`）；DSH 命令可用 `RESULT_SERVICE_DSH_COMMAND` 指定（`result_service/README.md`）。
- 调度器离线时界面仍可查询数据库、生成报告与打开助手；只有管理类操作会报错。

### 6.4 日志

- 调度器：`server.log_file` 非空时写文件，启动时会先尝试以追加方式打开并探测可写性，失败则直接抛错（`scheduler/src/main.cpp`）。一键部署把它设为 `runtime/logs/scheduler.log`。
- 结果服务：日志集中在 `logs_dir`，界面的"日志"页只列该目录下的文件并做有界截断，不接受浏览器传入任意路径。

## 7. 提交前自检清单

1. `cmake --build build/rt --config Debug --parallel 8` 无警告级别的错误。
2. `ctest --test-dir build/rt -C Debug --output-on-failure` 通过；本机不具备 PostgreSQL 时，集成用例不会被注册，属于预期。
3. 改动插件接口（`TaskPlugin` / `WorkerPlugin`）时，同步重建**调度器与全部插件 DLL**，并在交付说明里注明必须整体升级。
4. 改动打包脚本时，`test_package_portability.py` 覆盖组件包契约：`-OnlyClient`/`-OnlyProgram`/`-OnlyDataset` 三选一、组件更新不重写部署 endpoint 与数据库设置、`-OnlyDataset` 允许在空目录产出且不生成 `config/client.json`。
5. 改动归档脚本时，`test_package_portability.py::SourceArchiveTests` 用严格集合比对归档内容，`runtime` 根下的生成文件、`.git`、`service-workspace` 都不得入包。
