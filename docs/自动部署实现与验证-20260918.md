当前按单客户端单插件使用：每个客户端的生效配置必须恰好包含一个 `enabled=true` 的业务插件。Agent 继续管理一个 Worker 子进程，保留异常恢复、制品下载、更新切换和回滚；调度与部署均使用基础 `worker_id`。服务端仍可同时服务启用不同插件的不同客户端。切换插件的 patch 必须显式关闭旧插件并启用新插件。

单客户端多插件调度延后为低优先级需求；有序插件候选列表、机器统一请求和任务类型保持策略留待该需求恢复后设计。以下实现表和 34/34 测试结果记录的是 9 月 18 日状态，不作为本次范围调整后的验证结果。

9 月 20 日已落实启动、Worker 加载和更新激活时的单插件检查。更新工具在下载前校验基础配置与 patch 的合并结果；服务端提前拒绝明确同时启用多个插件的 patch。无效更新保留原生效配置，支持显式关闭旧插件后切换到另一个插件。

本次 Release 构建成功。针对性 CTest 共 5 组通过：`test_client_protocol`、`test_client_startup`、`test_client_deployment_integration`、`test_result_service`、`test_result_web`；另运行 `test_client_update.py` 15/15 和 `test_deployments.py` 18/18 用例通过。覆盖启动拒绝多插件、禁用插件不影响启动、下载前拒绝无效更新、历史准备配置检查、正常单插件切换、Worker 异常清理与重启，以及更新回退和报告确认。PowerShell 解析和 `git diff --check` 通过，本次未重跑全部 34 组测试。

## 2026-09-18 实现记录

| 场景 | 9 月 18 日记录的行为 |
| --- | --- |
| 插件、程序、数据上传 | 网页上传到服务端 HTTP 制品仓库；同类型、名称、版本不可替换内容，下载校验 SHA-256 |
| 客户端部署 | 保存所选制品和配置覆盖，按 revision 拉取、准备、切换、上报；支持发布历史版本进行回滚 |
| 更新不中断在执行任务 | 下载准备期间旧进程继续工作；切换前停止领任务，等待已开始任务及结果 ACK 完成 |
| 更新失败恢复 | 新进程启动或注册失败恢复旧版本；记住失败 revision，修正后发布新 revision；重启补发失败状态 |
| Worker 进程管理 | 9 月 18 日实现过每插件独立子进程及异常退出清理；多插件并行已于 9 月 20 日移出当前支持范围 |
| 时间控制 | 执行和更新时间窗分开；执行窗口关闭后继续完成当前任务与结果上报 |
| 任务队列 | 每插件持久 FIFO，支持选定客户端；服务器重启恢复运行及队列；配置变化时阻止不兼容的恢复或排队执行 |
| 重复执行提示 | 同一执行身份已有活动运行或完整成功记录时默认拒绝；强制重跑需原因；业务失败的已结束运行可普通重试 |
| 多人使用 | DSH 按浏览器操作身份分开会话；部署和展示配置保存校验 revision，拒绝覆盖他人的新版本 |
| STP 双程序 | baseline、candidate 分别接收输入文件和输出目录；各自生成 `info.txt`、`info_new.txt`，四份原始结果原子入库 |
| 插件背景说明 | 内置插件分别提供 `AI_CONTEXT.md`，说明职责、存储和使用约定 |
| 覆盖率分析 | 提供只依赖数据库的精简 STP 集合报告，使用确定性贪心筛选，不保证数学意义的全局最小集合 |
| 文件大小入库 | manifest 可记录字节大小和内容摘要，并持久化到 `plugin_run_files`；旧数据缺失值保持未知 |

操作和配置示例见 [自动部署使用指南](自动部署使用指南.md)。

## 2026-09-18 核对修复

1. 将运行结束与业务成功分开判断。`finished` 本身不能证明任务全部成功；去重查询同时检查任务报告和退出码。
2. completion journal 保存实际退出码。服务端在插件完成记账、框架任务状态尚未写入时退出，恢复对账可补回成功或失败证据；旧记录没有退出码时保留未知。
3. 修复客户端保存失败 revision 后、写失败报告前退出导致网页长时间显示“应用中”的问题。重启后保留并补发失败报告，不重复激活该失败版本。
4. 普通文件缓存同时考虑内容和文件名，避免相同字节、不同文件名互相覆盖；原始下载仍按内容复用。
5. 展示配置保存采用 revision 校验和原子替换；轮询不会自动改变未保存草稿的基准版本。发生冲突时保留草稿。
6. 数据库迁移测试按实际解析到的表检查字段，避免不同 schema 下同名表影响结果。

## 尚需协调的部署事项

当前自动化覆盖客户端插件、业务程序和数据分发，以下部分仍需显式操作：

- 上传插件不会自动安装服务端调度 DLL、结果适配器、AI 文档或 manifest，也不会热加载服务端插件；需安装配套资源、配置并重启。
- 任务指纹使用预期程序版本，尚未自动关联所选程序制品的 SHA-256。程序内容变化必须更新版本，数据变化必须重新生成 manifest；缺少预期程序版本时不能依赖去重保护。
- 框架 EXE 升级仍通过完整发布包；客户端包与生效配置保持单插件，切换插件需显式关闭旧插件。9 月 18 日的多插件启用方式不再适用。
- 时间窗和程序路径已能通过 JSON 配置覆盖，尚未提供完整的表单式发布向导。内置插件也未实现任意运行参数的业务含义。
- DSH 独立会话共享服务账户的文件、数据库和模型配置；会话隔离不等于文件权限隔离。
- 正式转换程序、OpenCppCoverage、全量 STP 数据和内网模型接口需在实际内网环境验收。本次没有重新制作最终离线发布包。

其他边界见 [已知限制](已知限制.md)。上述自动化回归和人工验证通过，不能替代正式数据及正式业务程序的环境验收。
