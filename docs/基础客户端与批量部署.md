# 基础客户端与批量部署

面向部署运维人员：新机器的首装、组件包更新，以及客户端常驻更新代理的工作方式与回执语义。

- 前提：**Windows x64**，目标机无需安装 Visual Studio、Python 或 Node.js。
- 全量离线部署见 [部署与运行](部署与运行.md)；方案/制品/滚动发布见 [部署方案与资源管理](部署方案与资源管理.md)。

## 1. 两种客户端形态

| 形态 | 内容 | 用途 |
| --- | --- | --- |
| 基础客户端（`-Bootstrap`） | `client.exe` + 框架 DLL（`common`、`libprotobuf`、`abseil`、`libpq`、`openssl`、`libzmq` 等按白名单过滤）+ VC 运行库 + `config/client.json` + `start_client.bat` + `tools/client_update.ps1` | 首装；**不含业务插件与程序**，插件、程序和数据由服务端按方案下发 |
| 完整客户端包 | 基础客户端内容 + 选中插件 DLL + `testenv\program` + `testenv\dataset` + `testenv\opencppcoverage` | 绿色整包分发；也作为后续组件更新的目标目录 |

两者都由 `tools/build_package.ps1` 生成，默认输出 `dist\client_package`，必须使用 `-Config Release`。

## 2. 基础客户端（首装）

### 2.1 生成

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build_package.ps1 `
    -Bootstrap `
    -DeploymentEndpoint http://192.168.1.10:56330 `
    -OutDir .\dist\client_base
```

约束与行为（`tools/build_package.ps1`）：

- `-Bootstrap` 必须给 `-DeploymentEndpoint`，且必须是 HTTP(S) 绝对地址，否则直接抛错；
- 输出目录必须为空，否则拒绝（避免覆盖已有客户端配置）；
- 不带 `-WorkerId` 时写入 `worker_id: "auto"`；Agent 首次启动会生成 `client-<随机>` 并**回写基础配置**，因此每台机器身份唯一。从同一份包复制多份到多台机器是预期用法；
- 生成的 `README.md` 说明首启行为与后续入口。

### 2.2 客户端目录结构

Agent 以**当前工作目录**为客户端根目录，配置路径由命令行给出，状态目录为 `<客户端根目录>\deployments`（`client/src/ProcessAgent.cpp`）：

```text
<客户端根目录>/
  client.exe
  config/client.json            基础配置（含 worker_id 与 deployment_endpoint）
  start_client.bat
  tools/client_update.ps1       更新代理（Agent 调用，不是独立启动器）
  deployments/
    update.lock                 单实例锁
    objects/<sha256>/archive            原始制品（ZIP）
    objects/<sha256>/content/           解包内容
    objects/raw/<content_and_filename_sha256>/content/   普通文件制品
    releases/<revision>/client.json     合并后的不可变配置
    active.json                 Agent 已确认注册成功的当前版本
    agent_report.json           待提交的部署状态回执
    failed.json                 失败锁存（修订号 + 原因）
    update_result.json          更新代理本次运行结果
```

### 2.3 启动与首装验证

```powershell
cd <客户端根目录>
.\start_client.bat
```

`start_client.bat` 执行 `client.exe config\client.json` 并 `pause`。首装验证顺序：

1. 客户端列表出现该机器：结果服务 → 客户端页，或 `Invoke-RestMethod http://<服务器IP>:56330/api/agents`；
2. 初始状态为"未配置/无插件"（Agent 状态 `unconfigured`），插件键为空；
3. 在部署页给该客户端分配方案（`plugin` + `program` + `dataset` 等资源），发布后 Agent 自动下载、暂存、切换；
4. 切换成功后客户端列表出现对应插件 Worker，状态变为 `ready`，`active_revision` 为新修订号。

## 3. Agent 与 Worker 的职责划分

- `client.exe`（无 `--worker-plugin`）= **Agent**：读基础配置，解析已启用插件，为每个插件启动一个 Worker 子进程，并监督其存活（崩溃后 1 秒重试）。用 job 对象与句柄白名单隔离，关闭 job 会连带结束插件残留的业务进程，不影响兄弟 Worker（`client/src/ProcessAgent.cpp`）。
- `client.exe --worker-plugin <name>` = **Worker**：完成注册、心跳、取任务、执行与上报（`client/src/main.cpp`、`Client.cpp`）。
- 多插件时 Agent 追加 `--qualify-worker-id`，Worker 传输身份变为 `<worker_id>/<plugin>`；单插件保持 `<worker_id>`。
- Agent 每 `client.deployment_poll_seconds`（默认 30）秒启动一次更新代理；`client.deployment_stage_timeout_seconds`（默认 0 = 不限）为代理单次运行上限。

## 4. 组件包：只更新一部分

三个开关**每次只能选一个**，否则直接抛错：

| 开关 | 作用 | 关键行为 |
| --- | --- | --- |
| `-OnlyClient` | 只更新二进制（`client.exe`、框架 DLL、VC 运行库、`client_update.ps1`） | 已有 `config/client.json` 时保留部署配置与插件选择，只更新显式传入的字段 |
| `-OnlyProgram` | 只替换选中插件的业务程序并推进其版本 | 保留数据集与其它插件程序；同步改写 `client.json` 中的 `target_exe`/`program_dir`/`engine_dlls`（stpcompare 为两个程序的 `executable`） |
| `-OnlyDataset` | 只替换 `testenv\dataset` 并推进其版本 | 重建 `version.txt` 与 `manifest.txt` |

示例：

```powershell
# 只换业务程序（已有客户端包目录，config/client.json 已存在）
powershell -ExecutionPolicy Bypass -File .\tools\build_package.ps1 `
    -OutDir .\dist\client_package -OnlyProgram -Plugin coverage `
    -StepTestExe \\share\release\StepTest.exe -OpenCppCoverageDir \\share\tools\OpenCppCoverage `
    -ProgramVersion 1.2.0

# 只换数据集
powershell -ExecutionPolicy Bypass -File .\tools\build_package.ps1 `
    -OutDir .\dist\client_package -OnlyDataset -DatasetDir \\share\dataset -DatasetVersion d2
```

必须知道的既有契约（有测试锁定）：

1. **组件更新不重写部署地址与数据库设置**。若在已存在 `config/client.json` 的目录上，对 `-OnlyProgram`/`-OnlyDataset` 同时显式传入 `-Endpoint`/`-DeploymentEndpoint`/`-ServerIp`/`-ServerPort`/`-DbConn`/`-DbPort`/`-DbName`/`-DbUser`/`-DbPassword`，脚本会在改动任何文件**之前**抛错并列出多余参数。要改地址请用完整打包或 `-OnlyClient`。
2. **组件包可以产出于空目录**：`-OnlyDataset` 在空目录只写 `testenv\dataset`，**不会生成** `config/client.json`；`-OnlyProgram` 在没有客户端配置时也允许执行（此时基于默认路径规则解析目标程序名）。
3. **组件更新的收尾提示与实际动作一致**：只有完整包才会提示"复制到目标机并运行 `start_client.bat`"；组件更新提示的是"复制到目标包目录"。该目录可能不含 `start_client.bat`，不要照搬首装步骤。
4. 程序单独更新时，如果配置里启用了多个插件且未显式传 `-Plugin`，脚本会拒绝执行并要求明确插件范围。

## 5. 部署代理：上传代理与执行流程

`tools/client_update.ps1` 只做"准备"，不替换活动文件、不启动或停止进程：

1. `GET /api/deployments/<worker_id>` 取期望态（携带 `-ConfigPath` 的基础配置）；无 `desired` 则写 `current` 并退出。
2. 若服务端已把该代标记为 `failed`，写 `rejected` 并退出——**该修订不再尝试**（见第 6 节）。
3. 逐个组件下载制品到 `objects`，校验 SHA-256（必要时校验 `size_bytes`），安全解包（拒绝越界路径），并写入 `content.json` 清单。
4. 把 `config_patch` 递归覆盖到基础配置上，生成 `releases/<revision>/client.json`（对象递归合并，标量/数组/null 直接替换）。
5. 把结果写入 `update_result.json`（`staged` / `waiting_window` / `failed` / `rejected` / `current` / `waiting_reservation`）。

Agent 随后决定动作：

- 校验 staged 配置 → 上报 `waiting_idle` → 向所有 Worker 发 drain 事件，等待在途任务与结果回执结束；
- 启动新 Worker；**全部注册成功后**才写 `active.json` 并上报 `ready`；失败则回滚到 `active.json` 指向的旧配置并上报 `failed`。

因此：**下载与暂存不中断业务，切换只在任务与回执清空后发生**。

## 6. 状态与回执语义

服务端记录的客户端协调状态（`result_service/README.md`、`result_service/app/deployments.py`）：

`unconfigured` → `pending` → `waiting_window` → `waiting_idle` → `applying` → `staged` → `ready` → `current`；失败为 `failed`。历史最多保留 10 代期望态。

回执规则：

- 回执必须列出**当前期望代的完整组件计划**，组件状态为 `pending`/`downloading`/`staged`/`active`/`failed`；整体为 `ready` 时每个组件都必须是 `active`。
- 重复提交同一份回执是幂等的。
- 回执对**旧代**提交时，服务端以 409 拒绝并且不保存——这是有意的：客户端每轮都会重新拉取当前期望态，旧代回执不会被当成当前安装。因此 409 不会让客户端失联，下一次轮询即恢复。
- 失败锁存：客户端一旦把某代判为 `failed`，只有**发布新修订**才会重试；即使之后下载条件恢复，也不会自动激活旧代（避免在没有预留的情况下激活）。同时服务端在终态失败后释放调度器预留。

## 7. 时间窗

- `execution_windows`：只影响新任务请求，窗口外 Worker 不再领新任务；
- `update_windows`：只影响下载与激活；
- 查询期望态与上报状态**不受窗口限制**；
- 两者都使用客户端本机时间，空数组表示全天开放。

## 8. 常见失败与处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 客户端一直 `unconfigured` | 未分配方案，或 `deployment_endpoint` 不可达 | 检查基础配置中的地址；确认结果服务端口开放 |
| 状态停在 `waiting_window` | 目标机当前时间不在更新窗口内 | 调整窗口或等待；查询/上报不受影响 |
| 状态停在 `waiting_idle` | 有长任务或结果未上报完成 | 等任务结束；确认插件上报正常 |
| 报告 `failed` 且不再重试 | 修订被锁存 | 修正原因（如补齐制品）后**发布新修订** |
| 制品校验持续失败 | 服务端对象字节损坏（内容寻址，重试拿到同样字节） | 由服务端重新上传该制品；必要时人工清理该客户端 `deployments\objects` 下对应 64 位哈希目录后由新修订触发重下 |
| Agent 起来了但没有 Worker | 配置里没有启用任何插件，或插件 DLL 缺失 | 检查 `config/client.json` 的 `plugins.*.enabled` 与包内 DLL |
| 需要换机身份 | 复制了同一客户端的 `config` 与 `deployments` | 复制整目录后删除 `deployments`（或至少 `active.json`），让 Agent 重新生成身份与激活路径 |
