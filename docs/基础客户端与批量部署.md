# 基础客户端与批量部署

新机器只复制基础客户端包。插件、被执行程序、数据和插件连接配置由服务端统一保存，再从“客户端”页面选择空闲机器发布。

## 首次部署

在已编译 Release 的源码目录生成一个未启动的基础包：

```powershell
.\tools\build_package.ps1 -Bootstrap `
  -OutDir .\dist\client-bootstrap `
  -BinDir .\build\offline_verify\bin\Release `
  -DeploymentEndpoint http://192.168.1.10:8080 `
  -ServerPort 5555
```

替换服务端 IP 和端口。默认从 HTTP 地址取得调度主机；调度器使用另一地址时传 `-Endpoint tcp://调度主机:端口`。输出目录必须为空，防止覆盖已部署机器的身份和配置。

基础包包含客户端管理进程、框架运行库、更新工具和启动脚本，不包含业务插件 DLL、被执行程序、数据集或插件数据库连接。将这个**未启动的包**复制到每台机器后，运行 `start_client.bat`。第一次启动生成并保存独立 `worker_id`，之后重启沿用。同一份已经启动的工作目录不能直接作为另一台机器的模板。

没有插件的客户端也每三秒发送独立心跳，页面显示“待配置”；下载较大资源不会阻塞心跳。服务端调度器和结果服务必须运行，客户端需要能访问管理页面端口、任务调度端口以及插件使用的数据库端口。

## 页面操作

1. 在“插件与部署 → 制品库”上传客户端插件、业务程序及数据制品。ZIP 内保留程序依赖、目录结构和启动时依赖的空目录（例如 OpenCppCoverage 的 `Plugins/Exporter`）；STP 数据包带有正确的 `version.txt`。数据变化时同时更新服务端 manifest 和预期数据版本。
2. 如果是新插件，先上传并配置配套服务端插件。服务端 DLL 变更仍需重启调度器，不能热替换正在使用的 DLL。
3. 在“客户端”页面选择一台或多台空闲机器，点击“配置所选客户端”。任意插件有在途任务、正在执行或尚未确认的结果时，整台机器不可选择。管理进程离线或已有更新预占时同样不可选。插件因旧程序版本或配置问题处于“启动中”，但管理进程在线且整机没有任务时，仍可下发修正配置。
4. 选择本次修改范围：插件启用状态、插件/程序/数据资源、运行安排。未指定的配置按每台机器自己的原值保留，不会复制第一台机器的完整配置。
5. 为第一次启用的插件选择已上传的插件包；内置插件还需选择 STP 数据包和程序制品，coverage 包括 OpenCppCoverage，stpcompare 包括 baseline/candidate 两个程序。填写对应包内路径，首次启用不能用本机绝对路径代替这些制品。服务端模板补齐数据库连接、默认参数等配置；模板中的服务器本机程序路径不会自动带到空客户端。
6. 预览每台机器合并后的配置；内置程序内容身份改变时保存服务端程序匹配配置，并按页面提示重启调度器。发布前重新核对预览。
7. 确认发布。服务端在派单队列中再次核对并预占全部目标机器；任意机器已忙碌或版本被另一位使用者修改，整批拒绝。可以保留草稿并重新预览。
8. 在逐台部署状态中等待“已生效”，核对插件 Worker 已注册，再创建任务。

变更目标机器时保留已填写的增量草稿，清除旧预览及程序匹配结果并回到第一步；重新预览后再发布。“清空本次修改”会明确清除草稿。历史回退仅在选择单台机器时出现，提交当前部署 revision 防止覆盖其他使用者的新配置；冲突后可刷新历史，增量草稿仍保留。

## 更新和恢复

- 预占期间，该机器所有插件都停止领取新任务。当前不在更新时间窗内时显示等待状态，预占保持到窗口打开。执行时间窗和更新时间窗相互独立；修改窗口本身也在旧窗口许可时生效。
- 客户端校验下载内容，准备新配置，停止插件 Worker，切换版本并重启 Worker。基础管理进程持续在线，无须手动整机重启，也不依赖 DLL 热插拔。
- 新 Worker 启动失败时先停止全部新 Worker、恢复旧配置，再报告失败并释放预占。旧插件暂未通过服务端注册时，仍可向空闲 Agent 重新发布修复配置；恢复配置不等同于旧程序已就绪。禁用全部插件后，基础 Agent 仍保持在线。
- 下载或激活失败的版本不会自动再次尝试。修正配置或制品后重新发布，即可生成新版本并重新预占、更新。页面历史回滚也遵守空闲校验。
- 调度器将 Agent 注册和预占写在 `config/runtime/client_control.json`，重启后恢复；客户端保留 `deployments` 下的生效及失败记录。不要在恢复过程中删除这些状态。
- 批量发布保证部署期望一次性保存，每台下载和激活独立推进。一台失败会回退该机器，不自动撤销其他机器已完成的更新。

服务端模板中的数据库地址必须是客户端可访问的内网地址；只有同机测试才能使用 `127.0.0.1`。客户端框架自身升级继续使用基础包/完整包维护，不通过业务插件制品覆盖运行中的 `client.exe`。
