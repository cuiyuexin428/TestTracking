### 3.2 scheduler 服务端框架

| 文件 | 修改内容 |
| --- | --- |
| `scheduler/inc/scheduler/Scheduler.h` | `ClientEntry` 的注册状态由 `bool registered` 改为 `unordered_set<string> registered_plugins` |
| `scheduler/src/Scheduler.cpp` | 见下方明细 |
| `scheduler/scheduler.json` | 启用默认本地 PostgreSQL：`server.db_conn` 不再为空 |

`scheduler/src/Scheduler.cpp` 具体修复：

1. **注册门禁按 plugin_type 隔离**  
   一个客户端只有注册成功的 plugin_type 才能请求任务，避免注册 A 插件后请求 B 插件任务。
2. **TASK_ACK 身份校验**  
   ACK 现在校验 identity 和 plugin_type，拒绝其他客户端对任务的错误确认。
3. **TASK_REPORT / TASK_REJECT 补充 plugin_type 校验**  
   防止任务被错误插件类型的结果关闭。
4. **createRun 完成清理竞态**  
   旧 run 已 `runFinished()` 但尚未被 500ms 定时扫描清理时，创建新 run 会先完成旧 run 的 FinishRun、erase 和 active_run_count 减一，避免计数漂移和旧 run 长期停留在 running。
5. **STOP 检查点保护**  
   若插件 `saveCheckpoint()` 返回 false 或抛异常，则保持活跃 run，不执行 cancel/FinishRun，避免保存失败时直接丢弃任务池。
6. **插件类型重复加载拒绝**  
   相同 plugin_type 只允许加载一次。
7. **WAKE 消息补齐 plugin_type**  
   按插件类型唤醒时在 Envelope 中写入 plugin_type。

### 3.4 coverage 插件

| 文件 | 修改内容 |
| --- | --- |
| `plugins/coverage/inc/coverage/SchedulerPlugin.h` | 新增 `last_checkpoint_save_ok_` 状态 |
| `plugins/coverage/src/SchedulerPlugin.cpp` | 见下方明细 |
| `plugins/coverage/src/ClientPlugin.cpp` | 非 dry-run 模式提前校验 target_exe/stp_root/opencppcoverage；dry_run_delay_ms 负值归零 |
| `plugins/coverage/src/CoverageStore.cpp` | 见下方明细 |
| `plugins/coverage/inc/coverage/CoverageStore.h` | 更新过时的“仅文件后端”注释 |

`scheduler/src/SchedulerPlugin.cpp` 具体修复：

1. **检查点保存结果真实传播**  
   `SaveCheckpointLocked()` 维护 `last_checkpoint_save_ok_`，`saveCheckpoint()` 根据真实保存结果返回 true/false。
2. **plan 初始检查点保护**  
   新 run 规划后若无法保存初始检查点，`plan()` 返回 false，不允许启动该 run。
3. **STOP 时检查点失败不 cancel**  
   与 scheduler 框架配合，保存失败时保留任务池和活跃 run。
4. **batch_size / task_size 校验**  
   任一小于等于 0 时 `init()` 直接失败，避免 BuildWaves 死循环。
5. **迟到/未知结果保护**  
   `processResult()` 对 tasks_by_id 中不存在的 task_id 直接丢弃，不再错误触发当前波次结算。
6. **cancel 清理 run_id**  
   防止停止后队列中迟到的结果继续按旧 run 结算。

`CoverageStore.cpp` 具体修复：

1. **PostgreSQL schema 初始化失败会返回 false**  
   原先建表失败只打日志，`init()` 仍成功。
2. **File 后端初始化校验**  
   `store_dir` 为空或无法创建时返回 false。
3. **File 后端导出接口遵守契约**  
   `exportWaveCovs` 和 `exportCumulativeCov` 现在将 cov 文件复制到调用方指定目录，而不是忽略 `dir`。

## 6. 部署与验证步骤

### 6.1 服务器本机

```powershell
# 1. 初始化数据库
powershell -ExecutionPolicy Bypass -File tools\init_database.ps1

# 2. 允许远程客户端连接本机 PostgreSQL
powershell -ExecutionPolicy Bypass -File tools\setup_postgres_remote.ps1

# 3. 共享目录 + 防火墙（管理员）
tools\setup_server.bat

# 4. 生成数据集清单
powershell -ExecutionPolicy Bypass -File tools\build_dataset_manifest.ps1

# 5. 重新构建并启动 scheduler
cmake --build build --config Debug
build\bin\Debug\scheduler.exe
```

服务器默认配置：

- ZMQ：`tcp://*:5555`
- 框架 DB：`host=127.0.0.1 port=5432 dbname=testtracking user=postgres`
- coverage 插件 DB：同上
- 默认启用重启恢复（running/stopped run）

### 6.2 客户端打包

```powershell
powershell -ExecutionPolicy Bypass -File tools\build_package.ps1 `
  -OutDir C:\Shared\client_package `
  -StoreType postgres `
  -DbPassword "你的数据库密码"   # 无密码环境可省略
```

脚本会自动生成：

- `endpoint = tcp://<服务器IPv4>:5555`
- `db_conn = host=<服务器IPv4> port=5432 dbname=testtracking user=postgres`

将 `client_package` 复制到其他机器后运行 `start_client.bat` 即可。
