# 四项修复与验证（2026-09-20）

范围：`codex/deployment-automation` 当前工作区。此次处理审查确认的四项问题，保持单客户端单插件范围；不包含提交、推送或重新制作离线发布包。

## 修复结果

1. **恢复读取故障保留进度。** 读取 checkpoint、部署身份或 completion journal 时，数据库查询失败、文件读取或目录枚举失败会阻止 scheduler 启动并保留原 run。存储恢复后使用原部署继续。记录确实缺失或格式不支持仍按不可恢复记录处理。
2. **运行参数与任务身份一致。** 新建 run 时，省略参数、空字符串、纯空白和空 JSON 对象统一为无参数；非空 JSON 对象稳定序列化。参数支持范围由插件校验，coverage 和 stpcompare 在入队前拒绝非空参数，强制重跑也不能绕过校验。自定义插件默认保留参数支持。
3. **DSH 保存报告脚本与 API 一致。** 原生 DSH 与普通聊天提示均要求先读取脚本及 revision，保存时携带该 revision 和当前 operator_id；遇到 409 保留草稿并读取、合并最新内容。原生 DSH 工具环境提供当前操作身份。
4. **迟到的更新结果不降级已生效部署。** 更新辅助进程返回的 revision 已经生效时，不再用 waiting_window、failed 或 staged 快照覆盖状态；其他新部署的等待与失败报告仍正常保留。

## 升级与验证边界

- `TaskPlugin::validateRunParameters` 改变了 C++ 插件接口，服务端和所有插件 DLL 必须同批重编译部署，不能混用旧二进制。
- 未完成运行先使用原 DLL、manifest 和配置恢复完成，再升级。现有运行参数和指纹不回写；新建参数规范化不是历史记录迁移，旧参数写法对应的历史指纹不保证被新版去重命中。重编译插件也会改变任务身份。
- 本轮没有增加单客户端多插件调度，也未改变任务执行与数据库分析分离的设计。
- 正式转换程序、OpenCppCoverage、全量 STP 数据及内网模型接口仍需环境验收。统一发布向导、服务端插件自动安装、程序制品 SHA 与任务身份绑定等暂缓项见 [已知限制](已知限制.md) 和 [自动部署使用指南](自动部署使用指南.md)。
