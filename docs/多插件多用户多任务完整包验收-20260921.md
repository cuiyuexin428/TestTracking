# 多插件、多用户、多任务完整包验收

日期：2026-09-21。平台：Windows x64。基线提交：`a460507`。

## 交付与实现

- `real-test/server`：Release 调度器、内置插件、结果服务源码与页面、离线 Python 分析运行时、PostgreSQL 运行时及维护工具。
- `real-test/client-01`、`real-test/client-02`：独立客户端包，均启用 coverage、stpcompare，携带完整测试数据和验收程序。
- 每个插件运行在独立 Worker 中，使用独立传输身份、session 和任务槽；物理客户端身份用于部署和界面聚合。
- 不同插件可以并行；同一插件的多个运行进入持久 FIFO 队列。相同任务默认拒绝，强制重跑需填写原因。
- 多人操作使用 revision 检查防止部署、配置和报告脚本被旧页面覆盖。DSH 按 operator 隔离会话、工作区记录和附件，复用服务器的模型配置与 skills。
- 部署向导独立保存各插件的程序、数据和执行模式。更换共享制品时保留自定义插件、禁用插件及未编辑字段的原绑定；冲突时分配独立槽位或明确拒绝。
- 执行与更新时间窗分别配置；部署激活等待所有插件完成当前任务和结果确认。每插件分别使用 `client.task_threads` 个槽。

多人会话标识按浏览器配置文件保存，同一配置文件的多个标签页共用身份。该机制不是登录、权限隔离或文件系统沙箱；数据库和项目文件仍是可信内网用户共享资源。

完整包验收使用独立 PostgreSQL 数据目录、真实调度器和四个插件 Worker，完成以下链路：

1. 两个并发运行请求只创建一条相同任务；强制重跑入队，另一插件同时执行。
2. 有任务在途时强杀调度器，再强杀整台测试客户端；重启后原运行恢复，排队任务自动完成。
3. 三个运行各完成 16 个输入，共 48 个任务。coverage 有实际 OpenCppCoverage 覆盖点和文件大小；stpcompare 入库 64 份 info 内容，即每文件新老程序各两份。
4. 已完成任务再次创建返回 409；配置与报告脚本的旧 revision 保存返回 409。
5. 停止调度器后，仅凭数据库生成 coverage Python 报告成功，验证执行与分析分离。
6. 实际上传两个插件和全量数据，客户端下载、激活成功；第二个插件 DLL 无效时自动恢复原双插件；显式回滚后状态恢复“已生效”。
7. 发布前核对在线结果服务、制品目录与在线调度器配置路径确实属于指定测试包，避免误用被其他进程占用的旧端口。

原始证据保存在 `real-test/evidence/acceptance.json`、`packaged-deployment.json` 和 `final-package-parity.json`；套件输出另存于 `out/final-ctest.log`、`out/final-packaged-acceptance.log`、`out/final-packaged-deployment.log`。上一轮环境保存在 `out/real-test-before-final-20260921`，未覆盖原证据。

## 使用当前环境

当前 UI：`http://127.0.0.1:56201/`。最新地址、进程标识和数据库端口见 `real-test/environment.json`。

当前保留一套服务和两台客户端进程，便于继续体验。需停止时，在仓库根目录执行：

```powershell
New-Item -ItemType File -Path .\real-test\stop.request -Force
```

停止后保留数据库和部署记录，再次启动：

```powershell
.\runtime\python\python.exe -B .\test\run_packaged_acceptance.py --serve-existing
```

验收监督进程只管理本次启动的进程；结束结果服务时一并终止其 DSH 子进程。复用启动另建证据目录，不覆盖已有记录。重新从空目录验收使用 `--out <新的空目录> --keep-running`，不要覆盖正在使用的包。

## 验证边界

业务程序使用本仓库编译的 native acceptance fixture，实际调用 OpenCppCoverage、生成四份 info、写数据库，但不实现正式 STEP 几何转换。因此正式新老业务程序和完整 STP 数据仍需在内网验收。DSH 本轮使用本机已配置模型完成聊天，未验证尚未接入的内网模型端点。

这些包是带测试配置和运行数据的操作验收环境，不应直接作为正式业务数据库交付。批量发布、断点续传和机器级总资源配额等现有边界继续见[已知限制](已知限制.md)。
