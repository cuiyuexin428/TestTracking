# 部署向导与插件安装验证（2026-09-20）

范围：`codex/deployment-automation` 当前工作区。本轮补齐程序制品身份、客户端部署向导、服务端插件及分析资源安装；保留单客户端单插件、仅 DSH，以及任务执行与数据库分析分离的设计。

本文是 [四项修复与验证](四项修复与验证-20260920.md) 和 [自动部署实现与验证](自动部署实现与验证-20260918.md) 之后的验证记录。历史记录中的测试数量和暂缓事项保留原样；当前使用方式与边界以 [自动部署使用指南](自动部署使用指南.md)、[服务端插件包格式](服务端插件包格式.md) 和 [已知限制](已知限制.md) 为准。

## 1. 实现结果

1. **程序制品内容参与任务去重。** coverage 和 stpcompare 使用制品路径时，从制品 SHA-256、包内程序入口和执行配置派生 `sha256:...` 程序版本。coverage 覆盖采集工具、模块列表、`store_cov` 和执行模式；STP 分别计算新老程序身份，参数引用的其他制品内容也参与计算。显示版本、制品编号、槽位别名和机器缓存路径不改变身份。客户端部署发布与服务端匹配配置使用同一套派生逻辑；原有本机路径和 `version.txt` 方式继续可用。
2. **客户端部署可通过表单配置。** 向导支持插件、程序、数据集、包内路径、STP 新老程序及参数、coverage 采集设置、并发数，以及独立的执行和更新时间窗。支持跨午夜窗口，保留高级 JSON 和未知配置字段；同一制品可以用于多个角色。预览显示最终配置和程序身份，保存服务端匹配配置与发布客户端部署分别操作。配置冲突保留草稿，较旧的异步预览不会覆盖新编辑。
3. **服务端插件包形成安装闭环。** 提供离线构建工具、ZIP 预览与安装入口。安装校验包结构、摘要和资源声明，将 DLL 写入独立安装目录，并为视图、适配器、AI 背景及可选报告模板建立完整资源快照。新插件默认禁用；升级保留既有业务配置、其他插件资源和用户报告脚本。配置写入有版本校验、备份和持久事务记录；启动先恢复中断安装，再加载分析资源。安装不自动重启服务。

程序匹配配置变更和服务端插件安装均检查相关插件的未完成运行，包括排队、执行中和停止后待恢复的运行。离线修改也需要数据库证明不存在未完成运行；无法确认时拒绝变更。配置变更后，在 scheduler 重启前阻止提交新运行，避免使用尚未生效的配置创建任务。

## 2. 构建与自动化回归

在 Windows x64 工作区执行：

```powershell
cmake --build build/rt --config Release -j 4
$env:TESTTRACKING_DSH_BUNDLE = 'C:\WorkSpace\dsh-inter\dsh-offline-bundle\dist'
ctest --test-dir build/rt -C Release --output-on-failure -j 3
git -c core.safecrlf=false diff --check
```

## 3. 浏览器与安装后启动验证

使用独立测试服务、私有配置和测试制品进行实际浏览器点击，未更改用户现有服务：

- coverage：选择插件、程序和数据，预览派生身份，保存服务端匹配配置，再发布客户端部署；页面显示重启提示及等待客户端状态。
- STP：选择新老程序，确认独立身份；配置工作日 18:00–08:00 执行窗口和不受限的更新窗口，保存匹配配置并发布。
- 服务端插件：预览 ZIP、执行安装，确认成功状态和重启提示。
- 检查 1366×900、1024×768 布局；未出现页面横向溢出，浏览器错误日志为空。
- 安装后实际重启测试 scheduler，确认从新安装目录加载 coverage DLL，同时加载派生程序版本，coverage 和 stpcompare 均正常发现。

测试服务和 scheduler 已停止，测试浏览器页已关闭。网页“发布成功”仅代表部署期望已保存；真实客户端拉取、应用和注册另由自动化集成测试覆盖，正式部署仍应逐台确认“已生效”。

## 4. 当前边界与部署要求

- scheduler 和结果服务仍需手动重启。新安装的服务端插件需明确配置并启用；本轮没有重启用户现有服务。
- 每台客户端恰好启用一个插件。当前逐台发布，没有跨机器与服务端配置的整体发布事务。
- 上传或发布数据集不会自动替换服务端 manifest 和预期数据版本，二者仍需配套配置。
- 内容派生身份覆盖内置插件的制品程序。本机程序、自定义插件及包外依赖的实际文件内容仍由使用者维护版本；重新打包导致 ZIP 字节变化时，制品身份也可能变化。
- 插件安装不更新框架 EXE，不检测二进制 ABI 兼容性，也不自动安装新增 Python 依赖。服务端、客户端与 C++ 插件需使用兼容构建；未完成运行先使用原 DLL、manifest 和配置恢复完成，再升级。
- 增量传输、断点续传和自动缓存清理尚未实现。正式业务程序、全量 STP 数据和内网模型接口仍需环境验收。

本轮未提交、推送，也未重新制作最终离线发布包；现有离线包不能视为已包含本轮改动。
